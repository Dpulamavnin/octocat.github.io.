# Laser Clean — размещение сайта

## Важно
Это полноценное приложение с заявками, приватными фотографиями и кабинетом владельца, а не набор HTML-файлов. Обычная загрузка по FTP на PHP-хостинг не запустит его.

В комплекте находится **исходный код**, не готовая скомпилированная сборка. Публичный запуск ещё не выполнен. Размещение требует настройки, описанной ниже.

## Самый простой запуск
Опубликовать проект в Lovable и подключить свой домен. Заявки, фото, отзывы и вход уже связаны с Lovable Cloud. Публикация выполняется отдельно, по команде владельца.

## Собственный хостинг
Текущая конфигурация рассчитана на Cloudflare-совместимый серверный runtime (TanStack Start + Nitro). Другой серверный runtime требует адаптации конфигурации и отдельной проверки. Для статического или PHP-хостинга нужна другая версия приложения.

1. Распаковать архив. Установить Bun и зависимости: `bun install`.
2. Подготовить собственный совместимый PostgreSQL/Auth/Storage сервис и применить SQL из `drizzle/migrations/0000_laser_clean_content.sql`. Миграция создаёт таблицы и правила доступа, но не пользователей и не хранилище.
3. Создать приватное хранилище `request-photos`, лимит одного файла 5 МБ. Доступ к фото выдаётся только сервером после проверки администратора.
4. Включить вход email/пароль с подтверждением почты. Добавить свой домен в разрешённые адреса возврата для регистрации.
5. Настроить переменные окружения на сервере: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`. В настройках сборки: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID`. Получать значения нужно у собственного поставщика сервиса. Приватный ключ никогда не помещать в `VITE_*`.
6. Приватные ключи Lovable Cloud недоступны для переноса. Текущий сайт связан с Cloud; внешнее размещение с собственным сервисом требует переноса данных и настройки входа.
7. Управляемый вход Google использует инфраструктуру Lovable. На внешнем размещении его необходимо отдельно адаптировать; email/пароль можно настроить у собственного сервиса.
8. Выполнить `bun run build` и развернуть результат средствами подходящего хостинга. Сгенерированный список маршрутов создаётся автоматически.
9. Зарегистрировать владельца, подтвердить email, затем безопасным серверным способом добавить его идентификатор в `public.user_roles` с ролью `admin`. Первый зарегистрированный пользователь **не** становится администратором автоматически.
10. Проверить отправку заявки с фото, закрытый доступ к заявкам, вход владельца, публикацию отзывов и редактирование услуг.

## Перед реальной рекламой
- Владелец должен предоставить телефон, ссылки на мессенджеры, адрес и часы работы. Сейчас контакты не выдуманы и отмечены как уточняемые.
- Цены не предоставлены. До ввода тарифов калькулятор предлагает индивидуальный расчёт. После ввода: базовая цена × площадь/количество; повышающие коэффициенты не придуманы.
- Фотографии сгенерированы для оформления; изображение «до/после» явно обозначено как иллюстрация. Замените его реальными работами через кабинет.
- Отзывы от реальных клиентов пока отсутствуют. Новые отзывы сохраняются непубличными до модерации.
- Для уведомлений Telegram необходимы серверные секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Код отправки подготовлен, но уведомления пока не активированы и не проверены. Email-уведомления ещё не подключены.
- Фото в отзывах и редактирование SEO в кабинете пока не реализованы; заголовки и описания страниц уже заданы отдельно.
- Перед открытием массовой рекламы желательно подключить CAPTCHA и распределённое ограничение частоты отправки. Сейчас есть проверка данных, форматов фотографий и скрытое антиспам-поле.

## Проверено
Публичные страницы, отдельная услуга, меню телефона, отсутствие горизонтальной прокрутки, отправка заявки с фото, сохранение отзыва для модерации. Автоматические тесты маршрута главной, семи статусов заявки и отсутствия выдуманной цены проходят. Вход владельца и его действия требуют назначенного владельца и пока не проверены сквозным тестом.
